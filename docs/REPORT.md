최초 작성일 2026-10-23. 2026-10-25에 Unity 전환 결과를 추가했다. 설계는 `docs/PLAN.md`, 설계 변경은 `docs/DECISIONS.md`, 플레이테스트 기록은 `docs/PLAYTEST.md`.

## Unity 전환 (2026-10-25)

현재 실행 엔진은 **Unity 6000.3.27f1 LTS, URP, C#**이다. `src/Echelon.Core`는 엔진과 독립된 10 Hz 시뮬레이션이고, `unity/`에 지형·장비·효과·침로·입력·전투 HUD·편성·가이드·튜토리얼·AAR·저장을 연결했다. `data/`가 유일한 정의 원본이며 Unity의 138개 JSON 복사본은 동기화 도구가 내용을 검사한다. Godot 코드는 이후 제거했고(D-045), Godot 4.7.2에서 뽑은 기준값은 `tests/golden`에 남아 `tools/check_golden.sh`로 비교한다.

### 자동 검증

- .NET/NUnit **335개**, 별도 통계 전투 **2개** 통과. `tools/run_dotnet_tests.sh`와 PowerShell 실행 경로를 모두 확인했다.
- Unity EditMode **303개**, PlayMode **2개** 통과. PlayMode는 실제 UI 버튼으로 편성 저장·불러오기·배치·전투·AAR을 진행하고, 실제 명령으로 튜토리얼 14단계를 완주한다.
- 문자열 명령 유형 `SEIZE`와 임무 목표의 소문자 `seize`를 혼동하지 않는 회귀 검사를 추가했다. 명령 수신 이벤트의 명칭이 정수로 변환되던 AAR 오류를 수정했다.
- Godot 참조 검증: **108개 테스트·563 단언**, 88개 스크립트 정적 검사, 샌드박스·스커미시 50틱 스모크 통과.

### 플랫폼·실행 검증

- 최신 소스로 `tools/build_unity.ps1 all`을 실행해 Windows·Linux·WebGL 빌드가 모두 성공했다(`build/validation/unity_all.log`). WebGL 출력은 `build/unity/web/index.html`이다.
- Windows와 Ubuntu 24.04 컨테이너의 Linux 플레이어 모두 실제 전투 50틱·시뮬레이션 5초를 통과했다. 상태 해시는 양쪽 모두 `-6359573958815337535`다. 무표시 Linux 컨테이너는 `SDL_VIDEODRIVER=dummy`가 필요하며, 일반 데스크톱 GUI 실행에는 사용하지 않는다.
- Windows 실행 파일만 별도 디렉터리에 복사하고 그곳에서도 같은 50틱을 통과해, 소스 디렉터리 없이 필요한 리소스가 포함됨을 확인했다(`build/validation/clean_player/clean_smoke.log`).
- 실제 창 모드의 AI 대 AI 전투와 AAR 저장·캡처를 확인했다. 청군 승리·붕괴 판정·결과 틱 5820·기록 시간 582.1초다(`build/validation/unity_aar.json`, `unity_aar.png`).
- Chrome WebGL 2에서 실제 샌드박스 버튼 클릭으로 전투를 시작하고 지형·부호·HUD를 캡처했다. Brotli 헤더 서버와 헤더가 없는 일반 `http.server`에서 모두 통과했다. `webGLDecompressionFallback`을 켜서 정적 호스팅도 지원한다(`web_brotli_console.json`, `web_plain_console.json`, 각각 `errors=[]`).
- WebGL 입력은 키보드·마우스로 제한해 미사용 게임패드의 장치 해석 오류를 막았다.
- 알려진 한계: Unity가 `ERROR: Shader`로 출력하는 URP의 `Hidden/CoreSRP/CoreCopy`, `Hidden/Universal Render Pipeline/StencilDitherMaskSeed`, `Hidden/Universal/HDRDebugView` 미지원 셰이더 3건이 남아 있다. 현재 게임 지형·UI 표시는 확인했으며, 검증 스크립트는 이 3건을 별도 경고 목록으로 보존하고 다른 미지원 셰이더는 오류로 처리한다.

## 성능 (M7 측정, 헤드리스, 이 세션 환경 2코어)

`tools/profile_sim.gd --extra=5`: 엘리먼트 297개·제대 95개, AI 대 AI 교전 1,500틱.

| 항목 | 최적화 전 | 후 |
| --- | --- | --- |
| 평균 틱 시간 | 17.5 ms | 15.4 ms |
| 최대 틱 시간 | 74 ms | 51 ms |
| 이동 / 탐지 / 통신 / 사격 | 11.1 / 3.9 / 1.1 / 0.9 ms | 8.9 / 4.0 / 1.1 / 1.0 ms |

1배속(10틱/초)이면 시뮬이 CPU 시간의 약 15%를 쓴다. 틱이 도는 프레임은 15 ms 안팎이 추가되므로 **300개 규모에서 60 fps 를 꾸준히 지키지는 못한다**(틱 프레임에서 순간 하락, 4배속에서 뚜렷). 남은 비용 대부분은 GDScript 루프(엘리먼트 이동, LOS 표본)이며, 다음 단계는 (1) 이동·LOS·경로 단순화를 GDExtension(C++)으로 옮기기, (2) 시뮬을 작업 스레드에서 돌리고 표현은 스냅샷을 읽기 중 하나다. 렌더링 프레임률은 GPU 가 없는 이 환경에서 잴 수 없었다.

## 밸런스 1차와 M7 당시 남은 문제

자세한 표는 `docs/PLAYTEST.md`.

- M6 직후 러시아가 6판 모두 5분 안에 붕괴(손실 약 3 : 51). 미군 차량 cost 상향, 원거리 명중 감쇠, AI 전력비 판단, 러 편성 보강, 배치 깊이 조정으로 **미 6 : 러 2**까지 맞췄다.
- **가장 큰 문제는 판의 길이**다. 40분 설계에서 실제 판은 7분 안팎, 정면 조우전 한 번으로 전투력 붕괴가 난다. 증원(T+10분)이 들어오기도 전이다. 지휘 지연(18~20초)이 의미를 가지려면 교전이 더 길게 펼쳐져야 한다.
- 지도·거점 배치가 비대칭이다(교차로 FOX 가 러시아 쪽에 치우쳐 FOX 를 잡으면 러시아 후방이 사거리 안).

## 후속 실험 (2026-10-25): 중앙 거점·전장 붕괴

D-043으로 FOX 교차로·마을·거점을 지도 중앙 (2000, 2000)으로 옮기고, 붕괴 기준을 전장 투입 부대의 누적 정상 가치 대비 현재 전장 가치 25%로 바꿨다. 대기 증원은 제외하고 도착한 증원의 정상 가치는 기준값에 한 번만 더한다.

변경 직전 코드와 같은 시드 1~8의 TF AI 대 AI로 비교한 결과, 평균 판 길이가 **7분 17초 → 11분 39초**, 중앙값이 **7분 9초 → 9분 33초**로 늘었다. 1차 증원(T+10분)에 도달한 판은 **0/8 → 3/8**이다. 승률은 미 6 : 러 2로 같고, 8판 모두 여전히 붕괴 종료다. 판 길이는 부분적으로 개선됐지만 40분 시나리오와 후속 증원을 활용하는 흐름에는 아직 못 미친다. 자세한 판별 기록과 전제는 `docs/PLAYTEST.md`에 있다.

후속 검증은 GUT 12개 스크립트 108개 테스트·563개 단언, 88개 스크립트 정적 검사 0건, 50틱 스모크(샌드박스·스커미시)를 통과했다. M1·M2 테스트가 끝난 전장을 `Battle.dispose()`로 정리하게 해 테스트 종료 시 리소스 누수도 제거했다.

## 하지 않은 것 / 알려진 한계

- 사람 플레이테스트 5판: 이 세션은 사람이 조작할 수 없어 AI 대 AI 기록과 양식만 남겼다. "제대 지휘가 재미있는가"의 판정은 양식을 채운 뒤에 가능하다.
- (선택 항목) 명령 로그 리플레이 세이브: 결정론(시드·명령)과 명령 객체 직렬화는 준비돼 있으나 저장·재생 기능은 만들지 않았다.
- 보병의 건물 점령, 공병, 연료, 반포병, 지도·시나리오 추가는 PLAN 13.2(범위 밖) 그대로.
- 엘리먼트 3D 표현은 장비별 저폴리 모델(차체 + 표적을 따라 도는 포탑, 경사 추종, 격파 시 포탑 들림)이다. 판독은 여전히 NATO 풍 부호가 주로 맡는다.
- 전투 효과(포구 섬광·포연, 예광탄·미사일 연기 꼬리, 명중 불티, 격파 화염과 불타는 잔해, 포탄 흙기둥·먼지 고리·포탄 자국, 연막 차장)는 표현 계층에서 그린다. Godot 참조 구현은 MultiMesh 2개, Unity는 배치 입자 렌더러를 사용하며 시뮬 해시에는 영향을 주지 않는다. 웹은 입자 상한을 낮추고 섬광 조명을 끈다.
